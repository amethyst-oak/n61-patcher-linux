01 / What this is

A second system, not an update.

The project adds a second APFS system volume and boots it through a tethered chain. Your existing iOS 12.5.8 installation is the starting point — this is not a normal IPSW restore.

01 — THE IDEA

Two iOS versions.
One very old phone.

Keep the native iOS 12.5.8 SystemA, then build iOS 13.7 as SystemB. Booting SystemB is tethered: after a restart, the Linux computer and DFU mode are needed again.

SystemA · 12.5.8SystemB · 13.7APFS
02 — THE HOST

Linux is the point.

The port replaces macOS-only tools with Linux alternatives for extraction, signing helpers, device-tree repacking and the kernel patch finder.

03 — THE REALITY

Experimental by design.

The end-to-end Linux run has been confirmed on one iPhone 6 and one Debian x86_64 laptop. Other hosts and devices are not validated.

02 / Compatibility

What works. What doesn't.

These are the project's published test notes, not promises about every device. A patch being present does not mean the hardware feature is fully working.

Read before proceeding

This is not a daily-driver build.

Touch ID is disabled. Audio recording and AirPods output are known problems. The boot arguments also disable AMFI and code-signing enforcement, and jailbreak tooling is installed. Cellular, cameras, GPS, Bluetooth, battery life and long-term stability have not been comprehensively tested.

03 / The walkthrough

From clean checkout to first boot.

A condensed guide based on the repository's Markdown docs. Open each step for commands and context. For a first installation, read the complete N61 and Linux notes as well.

Before you begin

You need a phone on the exact supported base build, a Linux machine with USB access, the firmware files, and enough disk space. The iOS 13 base tree alone is about 9 GB.

Full N61 guide ↗ Linux setup notes ↗ Known issues ↗
Back up first. The installer creates APFS volumes and writes system files. A mistake or an Apple restore can erase data. There is no one-command uninstall that removes only the added volumes.
01Check the deviceN61AP, iPhone7,2, native iOS 12.5.8 (16H88)+

This guide is for the non-Plus iPhone 6. Do not substitute an iPhone 6 Plus (N56), iPhone 6s Plus (N66), or a different iOS build. The profile checks the board and the native SystemA build.

Start with a backup and the stock volume layout. If you previously added APFS volumes with another dual-boot tool, the layout guard may refuse to continue. Do not edit volume numbers to force it.

02Prepare the Linux hostDebian / Ubuntu package names+

Install the host dependencies. apfs-fuse is not packaged in the standard repositories and must be installed separately; see the Linux notes for its build dependencies.

Shell · system packages
sudo apt install git build-essential clang lld llvm xz-utils p7zip-full dmg2img \
  libusb-1.0-0-dev libssl-dev xxd libblocksruntime-dev fuse3 ldid libusbmuxd-tools \
  gcc-aarch64-linux-gnu libc6-dev-arm64-cross qemu-user

sudo modprobe hfsplus fuse

You also need an iPhoneOS SDK (the project documents Theos iPhoneOS14.5.sdk as accepted) and Python 3.

03Clone and set up the projectSubmodules, virtual environment and helper tools+
Shell · project setup
git clone --recursive https://github.com/amethyst-oak/n61-patcher-linux.git
cd n61-patcher-linux
mkdir -p ipsw build "$HOME/.cache/n61-patcher-tmp"

python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt pillow pillow-heif

export IPHONEOS_SDK=/path/to/iPhoneOS14.5.sdk
.venv/bin/python tools/doctor.py
.venv/bin/python tools/setup.py

doctor.py reports missing requirements with hints. setup.py initializes submodules and prepares helper tools and donor files. Continue only when setup finishes with Tools ready.

04Fetch and verify the four IPSWsExact builds matter — don't swap in another release+

The downloader retrieves the exact Apple firmware files and checks their pinned sizes and SHA-256 hashes. Firmware itself is not included in this repository.

Shell · firmware
.venv/bin/python tools/fetch_ipsw.py --list
.venv/bin/python tools/fetch_ipsw.py
.venv/bin/python tools/fetch_ipsw.py --verify-only

The four files are: N61 iPhone 6 iOS 12.5.8 (your phone), N66 iOS 13.7 (donor), N71 iOS 13.7 (UI resources), and J96 iPad mini 4 iOS 13.7 (root filesystem and kernel). Keep the exact filenames listed in docs/N61.md.

05Generate the SSH ramdiskDFU mode, not Recovery mode+

Put the iPhone into DFU. The screen should be completely black; a cable/computer recovery screen is a different mode. On iPhone 6, hold Home and the side button together for 8–10 seconds, release the side button, and keep holding Home until the computer detects it.

Shell · create ramdisk
lsusb | grep -i apple

(cd tools/SSHRD_Script && ./sshrd.sh 12.5.8)
ls tools/SSHRD_Script/sshramdisk

The DFU device normally appears as 05ac:1227. Check that sshramdisk/ contains iBSS.img4, iBEC.img4, ramdisk.img4 and kernelcache.img4. An empty folder means the later ramdisk stage will not work.

Important: do not use the upstream generic mount_filesystems flow. Mounting the encrypted native Data volume can hang the APFS container.

06Run the profile check and dry-runInspect the plan before any write stage+
Shell · no install writes
.venv/bin/python n56patcher.py list --target n61-ios13
.venv/bin/python n56patcher.py all --target n61-ios13 \
  --workdir build/n61-current --dry-run

The dry-run prints the patches and planned flow. It does not talk to the phone, check the phone's APFS layout, or exercise the Linux-only install path. It is a plan review, not proof that the install will succeed.

07Install, build and boot iOS 13.7The destructive part — keep USB connected+

With the phone in DFU and all four IPSWs verified, run the full flow. This writes APFS metadata and the new system. Do not unplug the phone during a filesystem write.

Shell · install
sudo env TMPDIR="$HOME/.cache/n61-patcher-tmp" IPHONEOS_SDK="$IPHONEOS_SDK" \
  .venv/bin/python n56patcher.py all --target n61-ios13 \
  --workdir build/n61-current

The process creates SystemB and DataB, writes the iOS 13 tree, applies overlays, builds boot images and sends them. When the last stage asks for DFU again, re-enter DFU and leave the command running.

After boot, complete setup on the phone over Wi-Fi. This is not an Activation Lock bypass and it does not skip activation.

08Boot it again laterKeep your personalized boot bundle+

The second system is tethered. Keep the entire build/n61-current/ directory privately; it contains images paired with your phone's own boot ticket. For another iOS 13 boot, enter DFU and run:

Shell · tethered boot
.venv/bin/python n56patcher.py boot --target n61-ios13 \
  --workdir build/n61-current

Never use another person's IM4M or boot bundle. Do not rerun install, rootfs, or all just to reboot — those stages clear SystemB.

05 / Field notes

A few things worth remembering.

Some gotchas from the docs that are easy to miss when you're focused on getting the phone to boot.

01 · Device names

N56 is not N61.

N56AP is the iPhone 6 Plus. This project targets N61AP, the smaller iPhone 6. N66AP is an iPhone 6s Plus donor, not the iPhone 6 Plus.

02 · Keep the build folder

Your boot images are personal.

The generated images are tied to the phone's own ticket. Keep the build directory private and do not borrow someone else's IM4M or boot bundle.

03 · Recovery

Restore means start over.

An Apple restore removes this installation and returns the phone to stock iOS. There is no selective one-command uninstall for only the added volumes.
