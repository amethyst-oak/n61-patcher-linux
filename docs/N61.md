# iPhone 6 (N61AP): experimental iOS 13.7 second system, installed from Linux

[Upstream project](https://github.com/CelestialSayuki/n56-patcher) · [N61 profile](../targets/n61_ios13.py) · [Linux notes](LINUX.md) · [Known issues](KNOWN_ISSUES.md)

This guide installs iOS 13.7 beside iOS 12.5.8 on an **iPhone 6 (non-Plus)** using a **Linux computer**. The patcher is CelestialSayuki's iPhone 6 Plus project, adapted to the iPhone 6 by tlfares and ported to Linux here. This is an experimental port with missing hardware support, not an official iOS update or a daily-use system. No AI service is needed.

The Linux flow has been run **once, end to end, on one iPhone 6 from a Debian x86_64 laptop**, reaching the iOS 13.7 home screen. Treat your own first run as a test.

## Device names matter

| Board | Device | Product identifier | Role here |
| --- | --- | --- | --- |
| **N61AP** | **iPhone 6** | **iPhone7,2** | The device this guide targets; A8 |
| N56AP | iPhone 6 Plus | iPhone7,1 | The original upstream target; A8 |
| N66AP | iPhone 6s Plus | iPhone8,2 | iOS 13 phone donor; A9, **not** the iPhone 6 Plus |
| N71AP | iPhone 6s | iPhone8,1 | Matching 2× iPhone UI resources |
| J96AP | iPad mini 4 | iPad5,1 | iOS 13 root filesystem and kernel donor |

Use `--target n61-ios13` in **every** command. The profile checks the board rather than a fixed ECID or UDID.

## What works and what does not

These statuses come from the iPhone 6 testing done on the macOS-built version of this project. Only boot and basic system use were re-checked on the Linux-built install.

| Area | N61 status |
| --- | --- |
| Boot, display, touchscreen, SpringBoard | Reached and used |
| Wi-Fi | Working on the tested device |
| Setup / activation | Completes with the N61 telephony compatibility patch. This is not an Activation Lock bypass |
| App Store | Purchases and cloud downloads worked for the upstream tester; on the Linux tester's phone **auth successful** (needed StoreAuthFix by computershik. |
| Icons and Settings resources | N71 2× resources are used |
| checkra1n userland / Cydia | Installed; Cydia opens. Package installation is limited, see [KNOWN_ISSUES.md](KNOWN_ISSUES.md) |
| Touch ID | **Not working.** Disabled in the default kernel build (SEP transport errors when enabled) |
| Vibration | Working on the tested N61 and enabled by default |
| Audio | Speaker output works. Dictaphone recording does nothing; AirPods pair but cannot be selected as the output. The experimental `audio` transplant stays disabled |
| Health | Excluded; do not assume it works |
| Wallpapers | The original HEIC catalog is disabled (it caused a SpringBoard loop). The installer derives four light/dark JPEG pairs from the N71 rootfs |
| Bluetooth, cellular, GPS, cameras, sensors, battery life, stability | Not comprehensively tested. A patch being included is not confirmation that the feature works |

The iPhone 6 has a vibration motor, not the later Taptic Engine.

The second system boots **tethered**: a normal restart does not rerun the patched boot chain. Keep the Linux computer's `build/` folder and be ready to enter DFU.

## Before installing

- An **iPhone 6 / iPhone7,2 / N61AP** whose installed SystemA is **iOS 12.5.8, build 16H88**. The source checks that build. Other builds and devices are not covered.
- A **backup**. Installation writes APFS metadata and clears the destination SystemB tree. A mistake or an Apple restore can erase everything on the phone.
- The stock volume layout: iOS 12 volumes `s1`, `s2`, `s3`, then the tool adds `s4` and `s5`. The layout guard checks volume names, slices and superblock checksums and refuses unrelated layouts. If you previously added volumes to this phone (for example with another dual-boot tool), the guard will refuse; do not edit volume numbers to force it.
- A Linux computer set up as in [LINUX.md](LINUX.md) (`tools/doctor.py` must report all required items present), a direct USB data connection (a USB 2 port or hub if DFU is unreliable), and disk space for four IPSWs, their extracted filesystems and the build output. The iOS 13 base tree alone is about 9 GB.
- Use a phone you can afford to experiment with. The port disables code-signing enforcement and installs jailbreak tooling.

## 1. Clone and set up the tools

```sh
git clone --recursive https://github.com/amethyst-oak/n61-patcher-linux.git
cd n61-patcher
mkdir -p ipsw build "$HOME/.cache/n61-patcher-tmp"
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt pillow pillow-heif
export IPHONEOS_SDK=/path/to/iPhoneOS14.5.sdk
.venv/bin/python tools/doctor.py
.venv/bin/python tools/setup.py
```

`tools/setup.py` initializes the submodules, builds or fetches the helper tools, and prepares `donors/`. If the checkra1n download fails, see "checkra1n 0.12.4 files" in [LINUX.md](LINUX.md). The message **Tools ready** means it finished.

## 2. Download the IPSWs

The downloader fetches the four exact IPSWs from Apple's HTTPS CDN and verifies pinned size and SHA-256. The repository contains the manifest, not Apple firmware.

```sh
.venv/bin/python tools/fetch_ipsw.py --list           # show URLs and hashes
.venv/bin/python tools/fetch_ipsw.py                  # download and verify
.venv/bin/python tools/fetch_ipsw.py --verify-only    # check existing files
```

If you supply your own downloads, keep these file names:

```text
ipsw/iPhone_4.7_12.5.8_16H88_Restore.ipsw          # N61 (your phone)
ipsw/iPhone_5.5_13.7_17H35_Restore.ipsw            # N66, donor only
ipsw/iPhone_4.7_13.7_17H35_Restore.ipsw            # N71, UI resources
ipsw/iPad_64bit_TouchID_13.7_17H35_Restore.ipsw    # J96, rootfs and kernel
```

The offsets target these exact builds; do not substitute other releases. The first extraction is cached in `ipsw/cache/`.

## 3. Generate the SSH ramdisk

Put the phone in **DFU**: the screen must be completely black (a recovery screen is not DFU). On an iPhone 6 hold Home and the side button together for 8–10 seconds, release the side button, and keep holding Home until the computer sees it. Check with `lsusb | grep -i apple` (DFU shows as `05ac:1227`).

Generate the ramdisk **once, with the iOS version as the argument**, then check that it produced files:

```sh
(cd tools/SSHRD_Script && ./sshrd.sh 12.5.8)
ls tools/SSHRD_Script/sshramdisk
```

The folder must list `iBSS.img4`, `iBEC.img4`, `ramdisk.img4`, `kernelcache.img4` and others. If it is empty, the later `ramdisk` stage will appear to send everything and then never answer. Do **not** use the upstream ramdisk's generic `mount_filesystems`: mounting the encrypted iOS 12 Data volume (`s2`) hangs the APFS container.

## 4. Check the profile (nothing is written)

```sh
.venv/bin/python n56patcher.py list --target n61-ios13
.venv/bin/python n56patcher.py all --target n61-ios13 --workdir build/n61-current --dry-run
```

A dry run prints the patches and the flow only. It does not talk to the phone, check its volume layout, or run the Linux-specific code paths, so it cannot prove an install will work. Warnings such as `No local IM4M found` and `boot_*.img4 missing` are normal at this point.

## 5. Install and boot

With the phone in DFU and the four IPSWs in `ipsw/`:

```sh
sudo env TMPDIR="$HOME/.cache/n61-patcher-tmp" IPHONEOS_SDK="$IPHONEOS_SDK" \
    .venv/bin/python n56patcher.py all --target n61-ios13 --workdir build/n61-current
```

The flow decrypts the native iBSS/iBEC, boots the ramdisk, extracts this phone's boot ticket, creates SystemB/DataB, writes the iOS 13 tree (tens of minutes), applies the overlays, sets APFS roles, builds the five boot images and sends them. When the last stage says it is waiting for DFU, put the phone back in DFU and leave the command running. Do not unplug the phone during a filesystem write.

Expected layout afterwards:

| Slice | Purpose | Mount used by the patcher |
| --- | --- | --- |
| `disk0s1s1` | Native iOS 12 SystemA | `/mnt1`, read-only |
| `disk0s1s2` | Native encrypted iOS 12 Data | not mounted |
| `disk0s1s3` | Baseband volume | role adjusted at the end |
| `disk0s1s4` | iOS 13 SystemB | `/mnt6` |
| `disk0s1s5` | iOS 13 DataB | `/mnt7` |

### Running the stages separately

The `all` flow is best for a fresh install. If the native boot inputs already exist, the stages are:

```sh
.venv/bin/python n56patcher.py ramdisk --target n61-ios13
.venv/bin/python n56patcher.py extract-im4m --target n61-ios13
.venv/bin/python n56patcher.py status --target n61-ios13
sudo env TMPDIR=... IPHONEOS_SDK=... .venv/bin/python n56patcher.py install --target n61-ios13 --workdir build/n61-current
sudo env TMPDIR=... IPHONEOS_SDK=... .venv/bin/python n56patcher.py build   --target n61-ios13 --workdir build/n61-current
# put the phone back in DFU, then:
sudo .venv/bin/python n56patcher.py boot --target n61-ios13 --workdir build/n61-current
```

Check the output of `status` before `install`: the volume layout must be the stock one. `install` is a **fresh SystemB install**, not a repair: the `rootfs` stage clears SystemB. Never re-run `install`, `rootfs` or `all` just to reboot an installed phone.

If `status` says "Ramdisk SSH is unavailable", the ramdisk is not running. Check that `sshramdisk/` is populated, re-enter DFU and re-run `ramdisk`. See [LINUX.md](LINUX.md#troubleshooting-on-linux).

## 6. First boot

Complete setup on the phone over Wi-Fi. This fork fixes the N61 radio-product mapping without spoofing the device identity. It does not skip activation or remove Activation Lock. Allow Cydia about 30 seconds on first boot for its background initialization.

## Subsequent boots

Keep the **whole** `build/n61-current/` folder privately. It holds the five paired images (`boot_iBSS.img4`, `boot_iBEC.img4`, `boot_DT.img4`, `boot_TC.img4`, `boot_KC.img4`). For another iOS 13 boot, enter DFU and run:

```sh
.venv/bin/python n56patcher.py boot --target n61-ios13 --workdir build/n61-current
```

The boot images are tied to **your phone's ticket**. After a stock restore, extract a new one and rebuild; an old bundle may hold a stale ticket. Never use another person's IM4M or bundle. For a kernel experiment, build into a **new** work directory (for example `build/n61-test`) and keep the working one; the trust cache is paired with the installed rootfs, so bundles and installs are not interchangeable.

## Variants

`--features` replaces the target's feature list and `--exclude` removes patches. For example, leaving out the `checkra1n` feature builds a boot chain without the checkra1n kernel patches:

```sh
F=pmu,touch,charging,chestnut,wifi,vibration,core,ui,bluetooth,baseband,sep
sudo env ... .venv/bin/python n56patcher.py build --target n61-ios13 --workdir build/n61-nojb --features $F
```

Two cautions. This was tried once and the phone behaved the same as with the default build, so it is **not a way to get a clean, unjailbroken system**: the installed system still contains the loader, `/binpack`, the launch jobs and the Cydia bootstrap, and the boot arguments still disable AMFI and code-signing enforcement. Excluding `rootfs.cydia` at install time (`--exclude rootfs.cydia`) is **untested**, and so is installing a different bootstrap on top.

## Touch ID and wallpapers

- **Touch ID** stays disabled. Restoring the sensor's initialization attaches the driver, but SEP transfers fail.
- **Wallpapers:** the installer generates the JPEG pairs with Pillow on Linux (`rootfs.adaptive_wallpapers`). `tools/n61_wallpapers.py` is a separate offline helper that still uses macOS `sips` and has **not** been ported. Do not copy the original HEIC catalog back; it caused SpringBoard restarts.

## Troubleshooting and recovery

| Symptom | Action |
| --- | --- |
| The computer never sees DFU | Retry the button sequence, use a data-capable cable and a USB 2 port or hub. A recovery screen is a different mode |
| `SystemA build` mismatch | Use a phone on 16H88. Do not edit offsets or suppress the check |
| Missing IPSW or donor file | Verify file names with `fetch_ipsw.py --verify-only` |
| Install stopped with an error | Save the output and note the failing stage. Do not re-run `rootfs` or `all` over a working install |
| `Connection reset`, `Permission denied`, or `iproxy` cannot bind | See the Linux table in [LINUX.md](LINUX.md#troubleshooting-on-linux). Stop only the conflicting `iproxy`, reconnect to the ramdisk and inspect the layout before any write |
| `Resource busy` after mounting native Data | Re-enter DFU, boot the ramdisk again and avoid mounting `s2` |
| Activation says a value is missing | Confirm the N61 target and its baseband overlay were used. Do not use Configurator as a workaround |
| A boot experiment loops | Re-enter DFU and send the last working bundle with `boot` |

A Finder or Apple Configurator **Restore** erases this installation and returns the phone to stock iOS. This fork has no one-command uninstall that removes only the added volumes. After a restore you can run the install again from step 3.

## Reporting a problem

Include the commit, `--target`, device model, native iOS build, the failing stage, the feature list and a short redacted excerpt of the output. Remove ECID, UDID, serial number, account details and activation data. Never upload `state/`, keybags, IPSWs or device-personalized images.

## How the port was made

The N61 profile keeps the J96 iOS 13 base, switches native extraction and the DeviceTree/touch configuration to N61, maps the native `tempranillo` Wi-Fi blobs to the donor kernel's `barbera` names, copies the native N61 model files, and adds N61's Mav10 entry to the telephony table. UI resources come from the N71 2× donor. The Linux port adds a host layer that swaps the macOS-only tools (see [LINUX.md](LINUX.md)).
